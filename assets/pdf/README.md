# Generated PDFs

PDFs are build artifacts and are not committed to Git. Generators write to
`pdf-output/`; copies in `assets/pdf/` are served by Eleventy.

## Files and Availability

| File                        | Contents                                                             | Generated by                                             |
| --------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------- |
| `chapter-XX-section-YY.pdf` | Individual section                                                   | Pages deployment and quarterly/manual workflow           |
| `chapter-XX-intro.pdf`      | Chapter introduction                                                 | Pages deployment and quarterly/manual workflow           |
| `chapter-XX-complete.pdf`   | Chapter introduction and all its sections                            | Pages deployment and quarterly/manual workflow           |
| `complete-book.pdf`         | Preface, all chapter introductions and sections, and both appendices | Quarterly/manual workflow or `npm run generate:pdf:book` |
| `complete-book.json`        | Complete-book source page ranges and total page count                | Complete-book generator                                  |

The current table of contents has 241 sections and 34 chapters, producing 309
chapter/section PDFs, plus the optional complete book. Counts follow `SUMMARY.md`;
file sizes and generation times depend on the content and machine.

Chapter and section downloads are hosted on GitHub Pages. The Pages deployment
does not generate the complete book, so the Preface and Summary complete-book
buttons require a separately supplied `complete-book.pdf`. Vercel builds do not
generate PDFs. Use the
[`pdfs` GitHub Release](https://github.com/veillette/physics-book/releases/tag/pdfs)
for the complete book and release copies of individual chapter/section PDFs.

## Automated Generation

- **Every GitHub Pages deployment:** `.github/workflows/deploy.yml` builds HTML,
  generates chapter/section PDFs, copies them into `assets/pdf/`, rebuilds the
  site, and uploads the Pages artifact.
- **Quarterly or manual release:** `.github/workflows/generate-pdfs.yml` also
  generates the complete book. It uploads individual PDFs to the `pdfs` GitHub
  Release and retains an Actions artifact for 90 days. The scheduled run is at
  00:00 UTC on January, April, July, and October 1.

Both workflows use `.github/actions/generate-chapter-pdfs/`. If parallel generation
fails, the action runs `regenerate-failed-pdfs.js`, which retries a fixed list of
historically troublesome combined chapters. It does not discover and retry every
failed PDF.

## Manual Generation

Install Chromium once and start the dev server:

```bash
npm run generate:pdf:install
npm run serve
```

In another terminal:

```bash
# Chapter and section PDFs in parallel (default concurrency: 4)
node scripts/generate-pdf-parallel.js

# Optional: complete textbook and page manifest
npm run generate:pdf:book

# Copy generated downloads into the site
cp pdf-output/*.pdf assets/pdf/
```

Other generation modes:

```bash
npm run generate:pdf                  # Separate section and chapter-intro PDFs
npm run generate:pdf:combined         # Combined chapter PDFs
npm run generate:pdf:chapter -- 1      # Chapter 1 introduction and sections
MAX_CONCURRENCY=8 node scripts/generate-pdf-parallel.js
```

The parallel generator covers sections, chapter introductions, and combined
chapters in three phases. The complete book is a separate command. Combined
chapter concurrency is half `MAX_CONCURRENCY`, rounded down, with a minimum of two.
Navigation and PDF download controls are hidden in generated documents.
Combined chapters reuse each page's stylesheets (`theme.css`, `book.css`, and
`print.css`) and layout wrappers through `scripts/lib/pdf-content.js`, so they
print with the same styling as the section and intro PDFs.

See [scripts/README.md](../../scripts/README.md#generate-pdfjs) for complete-book
assembly and failure behavior.
